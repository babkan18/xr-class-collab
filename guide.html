CHAPTER 0

왜 지금 GitHub인가

GitHub는 전 세계 개발자가 코드를 저장하고, 기록하고, 함께 만드는 곳입니다. AI가 코드를 써 주는 시대에는 “무엇이 언제 왜 바뀌었는지”를 읽고 검토하는 능력이 더 중요해졌습니다.

1억 8천만+GitHub 개발자 수
1초에 1명2025년 새로 가입한 개발자 속도 (1년 3,600만 명)
6억 3천만전체 저장소 수 (2025년에만 1억 2,100만 개 추가)
약 80%가입 첫 주에 AI 코딩 도구(Copilot)를 쓴 신규 개발자 비율

출처: GitHub Octoverse 2025 (2025.10 발표)

AI가 Pull Request를 보낸다

사람이 Issue로 할 일을 적으면 AI 코딩 에이전트가 코드를 고쳐 PR로 제안합니다. 2025년 5~9월에만 100만 건이 넘는 PR이 이렇게 만들어졌습니다. 그 PR을 읽고 합칠지 정하는 건 여전히 사람입니다.

XR은 얼굴 위로

헤드셋에서 안경으로 무게가 옮겨 가고 있습니다. 2026년 1분기 스마트 글라스 출하는 약 225만 대로 1년 전보다 167% 늘었고, 2026년 한 해 1,360만 대가 전망됩니다 (IDC, 2026.6).

GitHub가 곧 포트폴리오

저장소, Commit 기록, GitHub Pages 주소는 “내가 무엇을 어떻게 만들었는지” 보여 주는 증거입니다. 만 13세 이상 고등학생도 GitHub Education 학생 인증을 받을 수 있습니다.

CHAPTER 3

Git이 기록하는 방법

Git은 변경 기록을 관리하는 도구이고, GitHub는 그 기록을 온라인에 올려 함께 쓰는 서비스입니다. 개발자는 내 컴퓨터에서 작업한 뒤 GitHub로 올리고(push), 친구의 변경을 내려받습니다(pull).

CHAPTER 4 · 1교시

나의 저장소 만들기

이 저장소는 3교시에 내 홈페이지가 됩니다. 이름을 정확히 맞춰 주세요.

  1. 오른쪽 위 + → New repository로그인한 상태여야 합니다. 이메일 인증이 안 되어 있으면 이 단계에서 막힐 수 있습니다.
  2. Owner: 내 계정 · Repository name: my-xr-universe소문자, 하이픈(-) 사용. 이름이 다르면 홈페이지 주소도 달라집니다.
  3. Public 선택 + Add a README file 켜기무료 계정의 GitHub Pages는 Public 저장소에서 사용합니다.
  4. Create repository완료 신호: 화면 왼쪽 위에 내아이디 / my-xr-universe가 보입니다.
!

저장소에는 닉네임과 아이디어만 올립니다. 실명, 전화번호, 학번, 비밀번호, API 키, 허락받지 않은 사진은 올리지 않습니다. Public 저장소는 전 세계 누구나 볼 수 있고, Commit 기록에도 남습니다.

CHAPTER 6 · 1교시

Commit · Diff · History

Commit은 설명이 붙은 저장 지점입니다. 게임의 세이브 포인트처럼 언제든 그 상태를 다시 볼 수 있고, Diff로 무엇이 바뀌었는지, History로 바뀐 길 전체를 읽습니다.

좋은 Commit 메시지 = 무엇을 + 어떻게

나중에 읽으면 모르는 메시지

  • 수정
  • 최종
  • ㅇㅇ
  • Update README.md

History만 봐도 아는 메시지

  • README에 XR 관심 분야 소개 추가
  • 닉네임을 NOVA로 변경
  • 프로젝트 상태를 '기획 중'으로 수정
  • Add XR portfolio template

History 보는 법: 저장소 첫 화면의 🕘 N Commits → 메시지 클릭 → 바뀐 줄 확인.

CHAPTER 7 · 2교시

Fork · Branch · Pull Request

남의 저장소는 내가 직접 고칠 수 없습니다. 대신 내 계정에 복사(Fork)하고, 새 갈래(Branch)에서 고친 뒤, 원본에 “이렇게 바꾸면 어때요?”라고 제안(Pull Request)합니다. 원본 주인이 검토(Review)하고 합치면(Merge) 반영됩니다.

순서대로 따라 하기

  1. Issue 읽기수업 저장소 → Issues → 수업 미션 #1. 무엇을 왜 하는지 확인합니다.
  2. Fork오른쪽 위 Fork → Repository name을 xr-class-collab으로 바꾸고 Create fork. 내 홈페이지 저장소와 이름이 겹치지 않게 합니다.
  3. Branch 만들기내 Fork에서 main ▾ → idea-01 입력 → Create branch: idea-01 from main.
  4. 내 파일 하나만 수정 → Commitcollaboration/ideas/student-번호.md에 닉네임·대상·불편·XR 경험·첫 실험을 적고, idea-01 브랜치에 Commit합니다.
  5. Pull RequestCompare & pull request → base는 강사 저장소 main, head는 내 Fork idea-01 → 제목과 본문(변경 내용·이유·질문, Refs #1) → Create pull request.
  6. Review친구 PR의 Files changed에서 바뀐 줄을 읽고 관찰·질문·제안 한 문장씩 댓글로 남깁니다.

Fork와 Branch, 뭐가 달라요?

왜 각자 다른 파일을 고칠까요? · 충돌(Conflict)

두 사람이 같은 파일의 같은 줄을 다르게 고쳐 동시에 합치려 하면, Git은 어느 쪽이 맞는지 스스로 정할 수 없어 멈춥니다. 이것이 충돌입니다. 오늘은 11명이 각자 student-01.md ~ student-11.md 중 자기 번호 파일만 고치기 때문에 충돌이 생기지 않습니다. 실제 팀 프로젝트에서도 작업을 파일·기능 단위로 나누는 이유입니다.

CHAPTER 8 · 3교시

GitHub Pages · 파일을 웹사이트로

저장소의 index.html을 GitHub가 대신 웹에 올려 줍니다. 서버를 빌리거나 설치할 필요가 없습니다.

  1. Add file → Upload files로 index.html 올리기ZIP은 압축을 풀고 파일만. 폴더째 올리면 주소가 달라집니다. 파일 이름은 소문자 index.html.
  2. Settings → 왼쪽 PagesSettings가 안 보이면 내 저장소가 맞는지 확인합니다.
  3. Source: Deploy from a branch · Branch: main · Folder: /(root) → SaveNone 상태로 두면 배포되지 않습니다.
  4. Actions 탭에서 초록 체크 확인노란 점은 진행 중. 기다리는 동안 친구 작품을 검토합니다.
  5. Pages 화면 위쪽에 표시된 주소 열기주소를 추측하지 말고 표시된 주소를 복사해 워크북에 붙입니다.

CHAPTER 9

안 될 때는 현상부터 나누기

“안 돼요” 대신 관찰한 현상 + 기대한 결과 + 최근에 바꾼 것을 말하면 원인을 빨리 찾습니다.

404 · There isn't a GitHub Pages site here
  1. 파일 이름이 정확히 소문자 index.html인가요? (Index.html, index.html.txt 안 됨)
  2. 저장소 최상위에 있나요? student/index.html처럼 폴더 안에 있으면 안 됩니다.
  3. Settings → Pages가 main / /(root)로 저장되어 있나요?
  4. Actions가 아직 진행 중인가요? 1~2분 기다린 뒤 새로고침합니다.
고쳤는데 예전 화면이 보여요
  1. Commit이 main 브랜치에 들어갔나요?
  2. Actions의 최신 실행이 초록 체크인가요?
  3. 강력 새로고침: Windows Ctrl+Shift+R, Mac Cmd+Shift+R. 또는 시크릿 창에서 열기.
내 닉네임 대신 기본 닉네임(XR Explorer)이 보여요
  1. MY_PROFILE에서 따옴표·쉼표·괄호를 지우지 않았나요? 워크북 M3의 코드 만들기를 쓰면 문법이 자동으로 맞춰집니다.
  2. 프롬프트북 P13으로 오류 줄을 찾을 수 있습니다.
  3. 수정한 파일이 정말 업로드한 그 index.html인가요?
홈페이지에 README만 보여요
최상위에 index.html이 없으면 GitHub Pages는 README를 대신 보여 줍니다. 파일 이름과 위치를 확인하세요.
Fork 버튼을 눌렀는데 이미 있대요
이미 Fork한 저장소가 있다는 뜻입니다. 내 계정의 저장소 목록에서 xr-class-collab을 열어 이어서 작업합니다. 새로 만들지 않습니다.
PR의 Files changed에 다른 파일도 바뀌어 있어요
실수로 다른 파일을 고쳤거나 main에서 작업했을 수 있습니다. 강사에게 PR 주소를 보여 주세요. 같은 브랜치에서 되돌리는 Commit을 추가하면 PR이 자동으로 업데이트됩니다.
저장소를 만들 수 없어요 · 이메일 인증
가입 이메일의 인증 링크를 눌러야 합니다. 메일이 안 오면 스팸함을 확인하고, Settings → Emails에서 인증 메일을 다시 보냅니다.
Public으로 올린 개인 정보를 지우고 싶어요
파일에서 지우고 Commit해도 이전 Commit 기록에는 남아 있습니다. 비밀번호나 키라면 즉시 해당 서비스에서 바꾸고, 강사에게 알리세요. 처음부터 올리지 않는 것이 가장 안전합니다.
