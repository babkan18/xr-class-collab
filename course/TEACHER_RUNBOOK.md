고등학생 XR 전공 기초 수준을 가정한 50분 × 3교시 수업입니다. 수업 중 최종 결과는 XR 아이디어 소개 웹 포트폴리오이며 실제 VR/AR 앱 구현과 구분합니다. 11명이 자기 기록과 협업 기록을 남깁니다.

3. 활동 번호 01–11을 배정하고 짝 4팀과 3인팀 1팀을 구성합니다.
4. 학생에게 수업 홈을 배포하고 제출할 LMS/폼/폴더를 별도로 안내합니다. 워크북에는 서버 전송 기능이 없습니다.
5. GitHub Pages 설정을 강사 계정에서 한 번 리허설합니다. 학생 개별 계정에 대신 로그인하지 않습니다.

## 협업 리허설
학생 개인 홈페이지 저장소는 my-xr-universe, 강사 저장소를 Fork할 이름은 xr-class-collab입니다. Fork 안에서 idea-활동번호 브랜치를 만들고 collaboration/ideas/student-활동번호.md 하나만 고칩니다. PR의 base는 chloeisLovely/my-xr-universe:main입니다. 학생 계정을 collaborators로 초대하지 않아도 공개 저장소의 Fork 방식으로 제안할 수 있습니다. 계정 정책에 따라 Fork/PR이 제한될 수 있으므로 사전 확인합니다.

강사는 Files changed에서 파일 범위와 내용을 읽고 피드백합니다. 개인정보·완료 과장·불필요한 파일 변경이 없으면 Merge합니다. 학생 PR은 Refs #1을 사용하며 Closes #1을 쓰지 않습니다. 학생 PR을 모두 수업 중 병합할 필요는 없습니다.

## 04. 게임의 저장 지점이 있다면?

[강사 설명]
어려운 구간에 들어가기 전에 저장해 본 적 있나요? 저장 지점이 있으면 새로운 시도를 하기가 편합니다. 프로젝트에도 “이때는 어떤 상태였는지” 남길 수 있다면 어떨까요?

[학생 참여 / 진행]
좋아하는 게임의 저장 경험을 1명에게 듣습니다. 이후 “프로젝트의 의미 있는 변경을 기록하는 단위를 Commit이라고 부른다”고 이름만 연결하고 자세한 구조는 뒤에서 설명합니다.

[예상 반응과 코칭]
게임 저장과 Commit은 완전히 같은 기능이 아닙니다. Commit은 기록할 변경을 확정한 스냅샷이며 파일을 편집했다고 자동으로 계속 생성되지 않습니다. 뒤에서 이 차이를 다시 짚습니다.

[이미지 안내] AI 생성 개념 이미지입니다. 실제 제품, 실제 수업 사진, 게임 화면이 아닙니다.

## 60. 수업 자료와 다음 시작점

[강사 설명]
